# GitHub：判断の記録

方針（`state.md` の `## Approach`）を捨てるときに読む。投稿するかどうかは呼ぶ側の手順が決める。

「何をしようとして、なぜやめたか」を issue のコメントに残す。後で同じチケットをやり直す人が、前の方針とやめた理由を知るため。検討の過程は書かず、結論と理由だけにする。見出しと項目名と本文はドキュメント言語で書く（`state.md` の文はそのまま貼らずに書き直す。日本語の例）：

```markdown
**tixforge <cancel | 巻き戻し | 手放す>**（<YYYY-MM-DD>）

- 方針：<Approach の採用案を 1〜3 行で>
- やめた理由：<ユーザーから聞いた理由>
- 到達したフェーズ：<Status>（ブランチ <Branch>。<残した／削除した>）
```

ブランチが無い（`Branch` が `—`）ときは、括弧ごと省く。

投稿する内容は、他の操作と同じ確認一覧で示して合意を得てから、`gh issue comment <番号> --body-file <一時ファイル>` で投稿する。tixforge はコメントを編集・削除しない。
