# まとめて渡された文から下書きを作る

ticket の create・edit と project init（リポジトリの作成・context）で、ユーザーが説明の文をまとめて渡したときに Read する。項目を 1 つずつ尋ねる代わりに、渡された文から全項目を埋めた下書きを作り、決まらない所だけを尋ねる。渡された文はユーザーが書いた中身なので、共通規約の「中身はユーザーが書く」の範囲に入る。呼ぶ側は、埋める雛形（項目の一覧）と、合意を得る場所（ゲート）を示す。

1. **振り分ける**：渡された文を雛形の項目に振り分け、その項目の形に整えて書く。文に書いてあることは、言い換えても意味を変えない。
2. **推測を分けて書く**：文から直接は言えないが筋の通る補い（受け入れ条件の言い換え、空のときや境界の値の扱いなど）は、末尾に `（推測）` を付けて書く。何を作るか・なぜ必要か・サービスの目的のような中身の核は、推測で書かない（3 へ）。
3. **決まらない所は埋めない**：文から決まらない項目は、推測で埋めずに空けておき、雛形に「未決事項」があればそこにも挙げる。
4. **下書きを示して、絞って尋ねる**：下書きの全体を示し、続けて次だけを一覧にして尋ねる（1 つずつ聞く方法には戻らない）：
   - `（推測）` を付けた所（このままでよいか）
   - 決まらない所（3）
   - 文の中の食い違い（両方を示す）
   - 抜けている観点（共通規約の「チケットを書く対話」の、エラーのとき・権限・空のときなど。質問として）
5. **答えを反映する**：確かめた推測は印を外し、答えをその項目に書く。「まだ決めない」と言われた所は未決事項に残す。`（推測）` の印を残してよいのは、呼ぶ側が許すときだけ（init の context）。チケットには残さない（確かめるか、未決事項に移す）。
6. 呼ぶ側のゲートで、全体に合意を得る。
