# まとめて渡された文から下書きを作る

ticket の create・edit と project init（リポジトリの作成・context）で、ユーザーが説明の文をまとめて渡したときに、その手順の指示で Read する。項目を 1 つずつ尋ねる代わりに、渡された文から全項目を埋めた下書きを作り、決まらない所だけを尋ねる。渡された文はユーザーが書いた中身なので、共通規約の「中身はユーザーが書く」の範囲に入る。呼ぶ側は、埋める雛形（項目の一覧）・既定のある項目・合意を得る場所（ゲート）を示す。

1. **振り分ける**：渡された文を雛形の項目に振り分け、その項目の形に整えて書く。文に書いてあることは、言い換えても意味を変えない。
2. **言い換えは印を付けて書く**：文に書いてあることを、項目の形（判定できる受け入れ条件など）にするために言い換えた所は、末尾に `（推測）` を付けて書く。文に無いこと（空のとき・境界の値・エラーのときの扱いなど）は書き足さず、手順 4 で質問する。
3. **文に無い項目**：
   - 呼ぶ側が既定を示した項目は、既定で埋める（下書きで既定と分かるように示す）。
   - チケットの「対象外」「未決事項」は「なし」で埋める（手順 4 で確かめる）。
   - それ以外は、推測で埋めずに空けておき、手順 4 で尋ねる。
4. **下書きを示して、絞って尋ねる**：下書きの全体を示し、続けて次だけを一覧にして尋ねる（1 つずつ聞く方法には戻らない）：
   - `（推測）` を付けた所（このままでよいか）
   - 空けた項目と、既定で埋めた項目
   - 文の中の食い違い（両方を示す）
   - チケットのときは、抜けている観点（共通規約の「チケットを書く対話」の、エラーのとき・権限・空のときなど。質問として）
5. **答えを反映する**：確かめた推測は印を外し、答えをその項目に書く。「まだ決めない」と言われた項目は、未決事項に挙げ、その項目には「未決事項を参照」と書く。ゲートに出す前に、空の項目が残っていないことを確かめる。`（推測）` の印を残してよいのは、呼ぶ側が許すときだけ（init の context）。チケットには残さない（確かめるか、未決事項に移す）。
6. 呼ぶ側のゲートで、全体に合意を得る。
